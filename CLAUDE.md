# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

"Velvet Runway" — the Enriquez family's aviation-themed website: live METAR/TAF weather, sunrise/sunset, winds aloft, a photo gallery, flight logbook, and local aviation events. Deployed to GitHub Pages at https://wightout.github.io/FamilyWebsite/.

Pure static site: vanilla HTML/CSS/JS, **no frameworks, no libraries, no build step, no dependencies**. Keep it that way — do not introduce npm packages or bundlers.

## Commands

There is no build, lint, or test tooling. The only commands are the two Node data scripts (Node >= 18 required, for global `fetch`):

```bash
npm run update-aviation   # node scripts/update-aviation.js — fetch NOAA METAR/TAF + winds aloft → data/aviation.json, data/winds.json
npm run update-gallery    # node scripts/update-gallery.js — regenerate the gallery section of index.html from images/
```

To view the site locally, open `index.html` directly or serve with any static server (e.g. `npx serve .`).

## Architecture

The entire frontend lives in two files:

- **`index.html`** (~1430 lines) — all markup **plus one large inline `<script>`** (from ~line 346 to the end) containing every feature. There are no separate JS files for the frontend. Sections within the script are delimited by `/* ========== NAME ========== */` comments (LOGBOOK, BUTTON HANDLERS, NEWSLETTER FORM, GALLERY LIGHTBOX, etc.).
- **`styles.css`** — all styling. Design tokens are CSS custom properties on `:root` (`--ink`, `--sun`, `--coral`, `--teal`, `--mint`, `--cream`, `--paper`). Fonts: Playfair Display (headings) + Manrope (body) via Google Fonts `@import`. Breakpoints at 900px, 600px, 420px, plus `@media print` styles for the logbook.

### Data pipeline: GitHub Actions → data/*.json → client fetch

Live data is fetched server-side by scheduled workflows, committed to `data/`, and the browser reads those JSON files — with a live-API attempt layered on top where CORS allows:

| File | Written by | Read by client | Freshness |
|---|---|---|---|
| `data/aviation.json` | `scripts/update-aviation.js` (CI, every 30 min) | Weather section fallback | Bot-committed every 30 min |
| `data/winds.json` | same script/workflow | Winds aloft fallback | Bot-committed every 30 min |
| `data/events.json` | manually edited | Events + hero sections | Manual |
| `data/logbook.json` | manually edited | Logbook seed entries | Manual |

**Live-first, static-fallback pattern:** the weather and winds sections first try the NOAA API (`aviationweather.gov/api/data`) from the browser through public CORS proxies (`api.codetabs.com`, `corsproxy.io`), and fall back to the committed JSON when that fails. Sunrise/sunset is live-only (`api.sunrise-sunset.org`). Weather auto-refreshes every 5 minutes; METAR/TAF older than 60 minutes get a "stale" flag.

### Duplicated config that must stay in sync

The airport/station lists exist in **two places**: `scripts/update-aviation.js` (`stations`, `windsStations`, `windsFcsts`, `windsAltitudes`, airport names) and the inline script in `index.html` (`airportData` with lat/lng, winds `<select>` options in the markup). Adding or changing an airport or winds station requires editing both files, and the `<select>` elements in the HTML.

Current airports: KPOC (Brackett Field — home base), KCCB (Cable), KRAL (Riverside). Winds stations: ONT, WJF, SBA, SAN at forecast periods 06/12/24.

### Gallery is generated — do not hand-edit

The gallery markup in `index.html` between `<!-- GALLERY:START -->` and `<!-- GALLERY:END -->` is regenerated by `scripts/update-gallery.js` (triggered by CI on any push touching `images/**`). It sorts images by file mtime (newest first) and derives captions from filenames (`warbird-field-selfie.jpg` → "Warbird Field Selfie"). Manual edits inside the markers will be overwritten; to change a caption, rename the file. Keep both marker comments intact.

Gallery images are kept ≤1600px wide (see `docs/superpowers/plans/`); new photos should follow the same `lowercase-hyphenated-description.jpg` naming.

### Client-side state (localStorage)

- `velvetrunway-logbook` — logbook entries added via the form, browser-local only. On load, seed entries from `data/logbook.json` are merged with local entries, deduplicated by `id` (seed wins). To make an entry permanent for everyone, add it to `data/logbook.json`.
- `velvetrunway-newsletter-done` — boolean flag remembering the signed-up UI state. Emails go to Formspree, not localStorage.

### Events date format

`data/events.json` dates must match `"Weekday, Mon D, YYYY"` (e.g. `"Saturday, Mar 22, 2026"`) — `isPastEvent()` in `index.html` parses exactly that pattern to filter/badge past events.

## CI/CD (.github/workflows/)

- **`static.yml`** — deploys the entire repo to GitHub Pages on every push to `main`. There is no build; what's in the repo is what ships.
- **`update-aviation.yml`** — every 30 min, runs the aviation script and commits `data/aviation.json` + `data/winds.json` as `github-actions[bot]` ("Update aviation weather data" — the bulk of the commit history).
- **`update-gallery.yml`** — on push to `images/**`, runs the gallery script and commits the regenerated `index.html`.

Because the bot pushes to `main` every 30 minutes, always pull/rebase immediately before pushing, and expect branches to fall behind `main` quickly.

## Code Conventions

- **Vanilla ES6+ only** in the browser; the `scripts/` files are CommonJS (`require`) Node scripts.
- **Safe DOM building:** the inline script constructs elements with `document.createElement` + `textContent` (see `buildEventCard`, `buildEntryCard`) rather than injecting HTML strings; an `escHtml()` helper exists for the rare template-string cases. Follow this pattern for anything rendering fetched or user-entered data.
- Accessibility patterns are established throughout: skip link, `aria-live` regions for dynamic status text, `role="dialog"`/`aria-modal` lightbox with full keyboard navigation, `.sr-only` labels. Preserve them when touching markup.
- JSON data files end with a trailing newline and 2-space indent (the scripts write them that way).
